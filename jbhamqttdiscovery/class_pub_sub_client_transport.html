Detailed Description

MQTT transport adapter for PubSubClient.

PubSubClient is a synchronous, polling-based MQTT client.

Limitations:

  • The host firmware MUST call mqtt.loop() frequently.
  • PubSubClient's default 256 byte packet buffer is too small for discovery payloads. This transport raises it to at least DEFAULT_BUFFER_SIZE in setServer(), and grows it further if a publish needs more.
  • QoS handling is best-effort (publish is always QoS 0, subscribe supports 0 and 1).
  • Connection events are detected via rising-edge logic in tick().
  • Reconnect attempts in tick() block loop() until the broker answers or the attempt times out (PubSubClient's socket timeout, 15 s by default).
  • The transport takes over PubSubClient's message callback.

void PubSubClientTransport::tick ( )
inlineoverridevirtual

Detect MQTT connection transitions and reconnect.

Called from HaDiscovery::tick(). It invokes the onConnect callback on a disconnected -> connected transition. After the first connect(), it also reconnects when the connection is down (see setAutoReconnect()).

Note
This does NOT replace PubSubClient::loop().

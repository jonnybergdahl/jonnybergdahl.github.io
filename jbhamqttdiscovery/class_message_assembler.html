Detailed Description

Puts together incoming messages that an MQTT client hands over in parts.

AsyncMqttClient and espMqttClient call their message callback once per received chunk, with the chunk's offset (index) and the full payload length (total). Payloads of more than a few hundred bytes, like retained discovery configs, often come in several parts. The transports collect them here and pass on whole messages only.

Parts of one message arrive in order and aren't mixed with other messages, so one buffer is enough. Used from the client's callback only, so it needs no locking.

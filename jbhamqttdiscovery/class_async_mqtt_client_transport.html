Detailed Description

MQTT transport adapter for AsyncMqttClient.

AsyncMqttClient is a fully asynchronous, event-driven MQTT client.

Advantages:

  • No polling required
  • Proper QoS support
  • Native connection callbacks

This transport provides the most reliable behavior for Home Assistant discovery and availability handling.

AsyncMqttClient keeps pointers to the host, client id, credentials and will instead of copying them. This transport keeps its own copies, so callers don't need to keep those strings alive.

Incoming messages split over several TCP packets are ignored. Discovery command payloads are short, so this doesn't happen in practice.

After the first connect(), tick() reconnects when the connection drops (see setAutoReconnect()). Turn this off if your firmware already reconnects with its own timer, as many AsyncMqttClient sketches do.

AsyncMqttClient ignores a TCP connect that fails right away (e.g. while Wi-Fi is down): no callback fires and the client stays in its connecting state, ignoring further connect() calls. tick() therefore gives up on an attempt after CONNECT_TIMEOUT_MS, resets the client and tries again later.

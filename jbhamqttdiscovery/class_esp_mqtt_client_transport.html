Detailed Description

template<class Client>
class EspMqttClientTransport< Client >

MQTT transport adapter for espMqttClient (https://github.com/bertmelis/espMqttClient).

espMqttClient is a maintained successor of AsyncMqttClient with the same style of API. This transport works with all its client classes; pass the class as the template parameter and include its header yourself:

#include <espMqttClient.h> // espMqttClient, espMqttClientSecure
#include <espMqttClientAsync.h> // espMqttClientAsync (needs AsyncTCP / ESPAsyncTCP)
#include <transport/EspMqttClientTransport.h>
espMqttClient mqtt;
EspMqttClientTransport<espMqttClient> transport(mqtt);

Who runs the client's loop():

  • espMqttClient on ESP8266: nobody else, so tick() calls it (callLoop = true, the default there).
  • espMqttClient on ESP32: its own task by default, so tick() must not (callLoop = false, the default there). If you create it with espMqttClientTypes::UseInternalTask::NO, pass callLoop = true.
  • espMqttClientAsync: its network callbacks drive it, so pass callLoop = false on ESP8266.

espMqttClient keeps pointers to the host, client id, credentials and will instead of copying them. This transport keeps its own copies, so callers don't need to keep those strings alive.

The transport takes over the client's onConnect, onDisconnect and onMessage callbacks (espMqttClient keeps only one of each by default).

espMqttClient refuses to publish while the largest free block of heap is below EMC_MIN_FREE_MEMORY (16 KB by default). On ESP8266 that's often all the time, so build with a lower value, e.g. -D EMC_MIN_FREE_MEMORY=4096.

espMqttClient hands over longer incoming messages in parts. The transport puts them together up to setMaxMessageSize() bytes (4096 by default) and drops larger ones.

After the first connect(), tick() reconnects when the connection drops (see setAutoReconnect()).

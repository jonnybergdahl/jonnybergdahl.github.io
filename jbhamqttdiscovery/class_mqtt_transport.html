Detailed Description

Abstract MQTT transport interface.

This interface decouples the Home Assistant Discovery logic from the underlying MQTT client implementation.

It supports both:

  • synchronous / polling MQTT clients (e.g. PubSubClient)
  • asynchronous / event-driven MQTT clients (e.g. AsyncMqttClient)

The transport is responsible only for:

  • connecting with the configured server, credentials and Last Will
  • reporting connection state
  • publishing MQTT messages
  • subscribing to topics and passing incoming messages on
  • notifying when a connection is (re)established

Transports copy every string passed to them, so callers don't need to keep them alive.

It does NOT manage Wi-Fi.

After the first connect(), transports reconnect by themselves from tick() when the connection drops, waiting longer after each failed attempt. Turn this off with setAutoReconnect(false) if your firmware reconnects itself.

◆ reconnectNow()

void MqttTransport::reconnectNow ( )
inline

Try to reconnect on the next tick(), without waiting for the backoff delay.

Call this when the network comes back, e.g. from the Wi-Fi "got IP" event, so the transport doesn't wait for the next scheduled attempt (up to the maximum delay). It also resets the delay. Safe to call from another task or an event callback; it only sets a flag. Does nothing before the first connect(), while connected, or when automatic reconnect is off.

Turn automatic reconnect on or off, and set its delays.

On by default. After the connection drops, tick() tries again right away, then waits minDelayMs, doubling after each failure up to maxDelayMs.

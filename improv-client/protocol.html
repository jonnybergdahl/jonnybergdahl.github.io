Protocol

Everything here is transport independent and has no third-party dependencies. The clients use it internally; you need it for the enums and result types, or to implement another transport.

Notes the specification leaves implicit:

  • The serial checksum is the sum of every frame byte from IMPROV through the data, keeping the low byte. Clients write a newline after each frame.

  • The RPC payload inside a serial frame has no checksum of its own. On BLE, the checksum is appended to the RPC payload.

  • On serial, a Wi-Fi scan returns one result per network, then an empty result. On BLE it returns one result with three strings per network.

Transport-independent parts of the Improv Wi-Fi protocol.

This module has no third-party dependencies. It contains the protocol constants and enums, the RPC encoding and decoding shared by serial and BLE, the serial frame codec, BLE service data parsing, and the dataclasses returned by the clients.

Specifications:

  • Serial: https://www.improv-wifi.com/serial/

  • BLE: https://www.improv-wifi.com/ble/

Example, encoding the Wi-Fi settings command from the specification:

>>> payload = encode_rpc_command(Command.WIFI_SETTINGS,
...                              encode_wifi_settings("MyWirelessAP", "mysecurepassword"))
>>> payload[:3].hex(" ")
'01 1e 0c'

class improv_client.protocol.SerialPacketDecoder[source]

Bases: object

Incremental decoder that finds Improv frames in a serial byte stream.

Devices usually log text on the same port, so anything that isn’t a valid frame is skipped. Feed it bytes as they arrive; it returns the complete frames found so far and keeps any partial frame for the next call.

>>> decoder = SerialPacketDecoder()
>>> frame = encode_serial_packet(PacketType.CURRENT_STATE, b"\x02")
>>> decoder.feed(b"[I][log]: hello\n" + frame[:5])
[]
>>> decoder.feed(frame[5:] + b"\n")
[SerialPacket(packet_type=<PacketType.CURRENT_STATE: 1>, data=b'\x02')]

improv_client.protocol.encode_serial_packet(packet_type, data)[source]

Encode a serial frame: IMPROV, version, type, length, data, checksum.

The checksum covers every byte from the header through the data. Clients write a newline after the frame; that isn’t part of the frame and isn’t added here.
